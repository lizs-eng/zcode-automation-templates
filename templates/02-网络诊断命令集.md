# 网络诊断命令集：CLI 工具连不上网时先跑这几条

> 适用场景：ZCode / 任何 CLI 工具报告"连不上 GitHub / pip 装不上包"时，按序诊断，2 分钟定位是"没开代理"、"代理开了但节点挂了"还是"其他问题"。来自真实自动化系统的实战命令集。

## 第 1 步：分清"谁连不上"

```bash
# 测代理端口（本机混合端口通常 7890，按你的客户端为准）
timeout 3 bash -c "</dev/tcp/127.0.0.1/7890" && echo "代理端口: 开放" || echo "代理端口: 不通"

# 分别测"经代理"与"直连"
curl -x http://127.0.0.1:7890 -s -o /dev/null -w "经代理: %{http_code}\n" --max-time 10 https://github.com
curl -s -o /dev/null -w "直连: %{http_code}\n" --max-time 10 https://github.com
```

## 第 2 步：按结果对号入座

| 现象 | 诊断 | 处理 |
|---|---|---|
| 代理端口不通 | 代理客户端没启动 | 启动客户端；确认"系统代理"开关已开 |
| 端口通，经代理全部站点 000 | 代理客户端在跑但**出口节点挂了** | 客户端"代理"页换节点，或更新订阅 |
| 端口通，只有个别站点 000 | 目标站对节点 IP 风控 | 换节点；或改走该站的官方 API 域名（常见可达） |
| 直连反而通、经代理不通 | 客户端规则把该站走了坏节点 | 规则里把该站设为直连（DIRECT） |
| pip 报 `Cannot connect to proxy` 但 curl 正常 | Windows 系统代理（注册表）毒化了 pip | 命令前加 `NO_PROXY="*"` 直连国内源 |

## 第 3 步：验证修复

```bash
curl -x http://127.0.0.1:7890 -s -o /dev/null -w "%{http_code}" --max-time 10 https://github.com
# 输出 200 = 链路恢复
```

## 给自动化任务的两条铁律

1. **把"启动代理客户端 + 打开系统代理"的授权预先写进任务的 prompt**，工具才敢自行恢复
2. **故障分类要写进任务**（端口不通=可自救；端口通但节点死=需人工换节点），否则任务会在死节点上无限重试
